# Agent working rules

## Stack

pnpm + TypeScript + React + Vite + Tailwind v4 + shadcn/ui, with a
Cloudflare Worker backend ("Workers with static assets" via
@cloudflare/vite-plugin, config in wrangler.jsonc) hosting a Durable Object
per game room (partyserver). Tested with Vitest (unit: `src/`, `worker/`,
`shared/`) and Playwright (e2e: `e2e/`), linted with ESLint, formatted with
Prettier.

- TypeScript runs side-by-side per the official TS 7 guidance: `tsc` (and
  `pnpm typecheck`) is the native TS 7 compiler via the `@typescript/native`
  alias, while the `typescript` package is aliased to
  `@typescript/typescript6` because typescript-eslint requires the TS 6 API.
  Do not "simplify" this to a single `typescript` dependency. Drop the dual
  setup only once typescript-eslint supports TS 7 natively.
- TS 7 removed `baseUrl`; keep `paths` entries relative to the repo root.
- Three TypeScript projects: `tsconfig.app.json` (src + shared, DOM lib),
  `tsconfig.worker.json` (worker + shared, Workers runtime types from the
  generated `worker-configuration.d.ts`), `tsconfig.node.json` (configs,
  e2e). `shared/` must stay runtime-agnostic: no DOM, no Workers globals.
- `worker-configuration.d.ts` is generated by `wrangler types` (gitignored);
  `pnpm typecheck` regenerates it. Rerun after editing `wrangler.jsonc`.
- Vitest runs with globals off; always import `describe`/`it`/`expect` from
  `vitest` in test files.
- `vitest.setup.ts` registers Testing Library `cleanup()` explicitly; do not
  remove it, or rendered components leak across tests.
- Add shadcn/ui components with `pnpm dlx shadcn@latest add <component>`.

## Workflow

After making changes from a prompt and BEFORE committing:

1. Author new tests covering the changes being made.
2. Update any documentation affected by the changes (README, this file).
3. Run `pnpm format-and-validate` and repair any regressions in-line. This
   includes the Playwright e2e suite; never skip it.

Commit in small, modular units (one logical change per commit).

## Product invariants

- **Game logic lives in `shared/` and is pure.** The Durable Object and the
  client both apply the same `applyEvent` reducer; the DO never mutates state
  outside the command → events → reducer path, and the client never
  computes game outcomes itself.
- **Events are the only way state changes**, each bumping `version`.
  Ephemeral messages (live dial moves, effects, shroud peeks) are never
  persisted and never carry a version.
- **The target is server-generated.** Clients animate to it; they never
  pick it.
- **Mobile first.** iPhone Safari is the primary surface: 44px touch
  targets, `100dvh`, safe-area insets, `touch-action: none` on the board,
  reduced-motion respected.
- **Never eject a player for a dropped socket.** Disconnected players go
  "away" after a grace period and keep their seat, team, and score.
- **Free to operate.** Cloudflare free tier only; SQLite-backed Durable
  Objects with WebSocket hibernation.
- E2e is hermetic: the Worker reads `GAME_SEED` and `GRACE_MS` from the
  wrangler `e2e` env so targets and timings are deterministic. The psychic's
  board exposes `data-target` so tests can aim the dial; the app installs
  `window.__gameStore` and `window.__wsDrop` for diagnostics.
- `SEGMENTS` (shared/game/geometry.ts) is the one wedge-width constant;
  scoring and rendering both derive from it.
- Protocol changes need the zod schema, the event union, the reducer AND a
  scenario test in `shared/game/commands.test.ts`. Bump `PROTOCOL_VERSION`
  when a change is not backward compatible; clients show a reload banner.
- Effects must never leak the target (no warmer/colder for the psychic).

## Gotchas

- wrangler environments do not inherit `durable_objects`; the `e2e` env
  declares the binding again.
- A server-initiated WebSocket close inside `onConnect` does not complete in
  local workerd; clients act on the in-band `error` frame instead.
- `tsc -b` build info (`node_modules/.tmp`) can go stale after tsconfig
  edits; delete it if typecheck results look wrong.
- Playwright drives WebKit with synthetic pointer events delivered in a few
  ms; wait for the phase the board expects before dragging or flicking.
